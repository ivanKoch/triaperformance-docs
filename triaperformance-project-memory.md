## Where the truth lives

The `triaperformance-docs` GitHub repo is the single source of truth, and as of **August 12, 2026 it is the *only* source.** ~~It syncs into this project~~ — **the project knowledge is now deliberately empty.** It used to hold hand-uploaded copies of 20 repo documents; they were always a day behind, they loaded automatically while the repo did not, and so a session was handed yesterday's numbers before it read anything current. Do not ask for uploads and do not read an empty knowledge base as missing context. The repo is connected at the start of every session.

🚨 **One exception, and it has cost real work: for anything that RUNS — n8n workflows, the live Caddyfile, a deployed script — the repo copy is documentation, not the live source.** *The running instance is.* **Before translating, quoting or editing n8n copy, ask for a fresh export.** *(Sept 5, 2026. A Portuguese email was written by translating the Spanish body in the repo's workflow JSON; the live email had been rewritten weeks earlier and the whole pitch it was translated from no longer existed. Iván caught it by reading the export.)* **Same class of failure as the project knowledge above — a stale copy that loads first wins by default.**

⚙️ **The Eleventy build needs delete permission on the repo folder, and the test suite depends on it.** *`npx @11ty/eleventy` unlinks stale files in `_site/`, which a session sandbox blocks by default, and `tests/` correctly refuses to run against a `_site/` older than `site/` — so a session that skips the permission grant gets a green build and a suite that never ran.* **Ask for it once, early, in any session that touches the site.** *(Sept 6, 2026.)*

**Brand history lives in `ai-infrastructure-documentation.md` §45, not in `brand-guidelines.md`.** *As of v1.1 the brand file carries no dated notes and nothing struck through: a changed decision is edited in place there and gets one line in §45. If a rule in it cannot be stated in one present-tense sentence, the decision underneath it is not finished.* **Do not re-introduce a changelog into that file.** *(Sept 6, 2026.)*

**Search it, don't preload it.** The doc index in the project instructions is the map — it says which file owns what. `grep` the repo, then read only the sections that matched. **Every business figure must come from a file read in the current session**; the catalogue count moved five times in six days, so a number recalled rather than read is a number that is probably wrong.

`open-loops.md` is the NOW/NEXT/LATER list — reading it from the repo is the first tool call of a working session, and updating it is the last. This memory is not a state file. If a fact belongs in a doc, it goes in the doc.

## Standing lessons — earned, not assumed

- **A partial crawl's failures are evidence about the crawl, not about the targets.** (The "6 dead plans" myth, July 2026 — recorded as fact for a week, then disproven.)
- **Nothing is done until Iván reports a real result from the live system.** Reading the code is not verification.
- **Narrow an agent's job to calling tested logic, never to authoring it.** Hermes narrated success while shipping broken code (July 17, 2026).
- **Infrastructure learning for its own sake is an anti-pattern.** Every build session must leave a durable asset behind.
- **Distribution over creation.** Most of this business is under-promoted, not under-built.
- **A doc that isn't corrected on the way past rots into a contradiction.** Numbers get restated across files; when one moves, the others don't follow on their own.
- **A check whose input is the thing being checked can only ever confirm it.** *(Aug 12, 2026.)* The plan-link checker skipped every row where `is_published != TRUE`, so it structurally could not find a plan wrongly marked FALSE — which was three of the four known failures. The same shape as verifying the inventory against a file derived from the inventory. Before trusting a verification, ask what it would look like if the thing were wrong in the *other* direction. If the answer is "identical", it isn't a check.
- **Liveness is not correctness, and the difference is where the expensive bugs live.** *(Aug 12, 2026.)* Twelve published plans linked to a *different* plan's TrainingPeaks page; a buyer paid and received the wrong product. Every one of those URLs returned HTTP 200, so the link checker — which tests that a URL is alive — passed them for months. Name the property actually being tested, and notice when it isn't the one that matters.
- **When a human error recurs, make it impossible rather than write the warning down again.** *(Aug 12, 2026, four instances in one day.)* A doc warning about pasting tokens failed twice, so the roster query now runs against a view that cannot return the column. Also: the build fails if a plan links to another plan's page, if an asset has no cache-bust fingerprint, or if a zone table is short a row. A guard costs one afternoon and never needs remembering; a note costs nothing and gets read once.
- **Check live state against the live system, never against the docs.** Three times now a "pending" written down has outlived reality — the "6 dead plans" myth, the `plans_raw` duplicate ghost, and a storefront that sat documented as undeployed for a week while live, holding four queued items behind a gate that had already opened. Deploy status, what's serving, what's Active: fetch the URL or run the query at the start of a session. It costs seconds; carrying the assumption forward costs weeks.

- **On a big job that could be driven by a reusable structure, build the structure FIRST.** *(Iván, September 8, 2026, after the exercise-library afternoon.)* The most expensive order is the one nobody chooses deliberately: **park the structural work, then do the content work by hand anyway.** Either alone is fine. Together they cost an afternoon of rework, because every tool built in the meantime was keyed on the thing the content pass was changing — names. Renaming broke the merge map three times; four CSV round-trips each reversed a decision made after the export, because there was no stable id to diff against. **Raise the "build the reusable thing from day 1" option at the START of a large task, not after the manual pass has already happened.**
- **When building an instance gets cheap, the missing abstraction stops announcing itself.** *(September 9, 2026, writing up the exercise-library afternoon — the diagnosis behind the lesson above.)* Nine artifacts were authored before anyone asked whether "an exercise" existed as a thing; it did not, and **188 real exercises were stored as 759 name+cue copies**, one movement carrying up to four names. *The old signal for "you need a schema here" was that copying was laborious — that signal is gone, and nothing in the work will now supply it.* ⚠️ **And it surfaced by accident**: no control in this repo could have found it, because none of them holds a concept of *the same movement* — it took wanting to film videos, the first task in fourteen months that required the entity to exist. **Before authoring instance N+1, ask what entity it instantiates and whether that entity has a home** — not "have I built this before" (answered by memory) but "does the thing this page is made of exist as data" (answered by looking). 🔑 **A canonical library nothing is obliged to consult is a suggestion**: the lookup step in the authoring runbook is the only fix that prevents recurrence rather than repairing damage.
- **A checker fed its own list can only confirm what its author remembered.** *(September 8, 2026 — the sharper sibling of the "input is the thing being checked" lesson above.)* The name audit carried a hand-written list of 15 clusters derived from **Spanish** divergences, so it was structurally blind to clusters where Spanish agreed and a translation did not. It reported PASS while eight were still split. **The fix was never more careful listing: the audit now derives its clusters from the decision file.** Ask where a checker's list of things-to-check comes from; if the answer is "whoever wrote it", it is a reminder, not a check.
- **Render the artifact and look at it. Every check in this repo tests values and links; none of them can see what the finished thing looks like.** *(September 11, 2026 — three defects in one day, all format, none catchable by any existing test.)* **The email body went out as `Hola,,,Aqui esta la guia:` — an array handed to an n8n `{{ }}` expression, which stringifies with commas.** *It had been doing that to the `runner_week` magnet for two days. The endpoint returned `200 {"ok":true}`, Telegram fired, Twenty got the Person, the token minted, the PDF downloaded, suppression worked — every assertion in a six-step runbook passed while the message itself was unreadable.* *The same day, the guide PDF printed "Iván Founder & Head Coach" on one line and put the medical disclaimer on its cover, both invisible in the HTML and in every grep.* 🔑 **The repo has five lessons about checkers being blind and none about this: a check can only assert what someone thought to assert, and nobody writes an assertion for "does this read like a human wrote it".** *Before calling any athlete-facing artifact done — email, PDF, page — open the finished output and read it. It costs one look and it is the only thing that catches this class.*
- **A rule in the repo that no authoring session consults is a rule that does not exist.** *(September 11, 2026 — the nutrition guide.)* `methodology.md` §8 opened with an explicit scope line — *"training + race fueling only. Never day-to-day diet, never weight loss (→ nutricionista)"* — and a 40-page athlete-facing guide breached it anyway, then needed two independent external reviews and 43 findings to rediscover a boundary already written down by its own author. **Worse, §8 also held better numbers than the guide on eight counts, so the guide was a downgrade of the method written by the person who owns the method.** 🔑 The repo's existing lessons are all about *checkers* — this one is about *authoring*: before writing content in a domain, open the doc that owns that domain, not to verify a fact but to find out what the scope is and what the numbers already are. **Ask "which doc owns this subject" at the start of an authoring task, the same way "which doc owns this figure" is already asked before quoting one.**
- **Docs are written in plain prose, and the repo does not diagnose itself.** *(Iván, September 11, 2026, after a review found `open-loops.md` at 187 KB with a 13 KB session-narrative header, 102 items averaging 1.8 KB, 214 alert emoji, and a 44 KB "Last updated" line in the infra doc.)* No alert emoji, no bold-italic narrative, no chained session summaries in headers, no "the lesson worth carrying" notes. An open item is at most four lines: what, what it waits on, where the detail lives. A finding about the repo itself (an inventory that drifted, a doc that got long) is acted on in the session that makes it or not written down — it never becomes an item. A lesson is written once, here, only if it changes how a future session behaves.
- **A content pass changes what a duplicate detector can see.** *(September 8, 2026.)* Harmonising cues made two pairs converge that had been correctly distinct that morning, and created one duplicate outright. **Run the dedup check after writing content, not only before.**
